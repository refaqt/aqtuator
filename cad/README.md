# CAD

FreeCAD models of the machine and the actuator. The X axis is the first design here: a base plate,
a linear scale mount, and two linear guides carrying a linear motor. First-order concept sizing is
in
[`simulation/cases/short-stroke-actuator-concepts`](../simulation/cases/short-stroke-actuator-concepts/).

**FreeCAD v1.1**, built-in Assembly workbench. To let an agent work in your open FreeCAD window,
set the connection up once: [`docs/onboarding.md`](../docs/onboarding.md#freecad-for-agents-optional).
Read [`doqs/docs/agent-cad.md`](../doqs/docs/agent-cad.md) before letting an agent touch a model,
[`doqs/docs/decisions/2026-06-24_freecad-master-sketches-body.md`](../doqs/docs/decisions/2026-06-24_freecad-master-sketches-body.md)
before starting top-down design, and
[`.agents/skills/freecad/SKILL.md`](../.agents/skills/freecad/SKILL.md) when something misbehaves.

| File or folder | Contents |
| --- | --- |
| `assemblies/` | Assembly documents linking module parts by relative path |
| `parts/` | One folder per part **we make**, each with its own `exports/` |
| `exports/` | STEP/STL of this module's assembly — generated, gitignored |
| `params/` | Parameter sets — `default.csv` plus sparse override files |
| `params.csv` | The active model — generated by `resolve_params.py`, gitignored |
| `params-table.csv` | One row per model — generated, committed |
| `build_model.py` | This part's geometry, and the only tool a module owns |

`.FCStd`, `.step`, `.stp`, `.stl` and `.3mf` are tracked with Git LFS (see `.gitattributes`).
Measurement data is **not** — it lives on Google Drive, which is what keeps LFS usage inside the
free tier.

## Parts we buy are not stored here

`parts/` holds only parts we make ourselves. Rails, blocks, motors and anything else bought from a
supplier live in the shared parts library at [`modules/stoq/`](../modules/stoq/), and the
assemblies link them from there by relative path.

| Bought part | Where the model lives |
| --- | --- |
| HIWIN HGR15R418H rail | `modules/stoq/modules/hiwin/modules/hgr-rail/cad/parts/` |
| HIWIN HGL15CAZBC+E2 block | `modules/stoq/modules/hiwin/modules/hgl-block/cad/parts/` |
| MAXWELL MK2-180 magnet track | `modules/stoq/modules/maxwell/modules/mk2-stator/cad/parts/` |

Two rules follow from that. Never copy a supplier file into `cad/`: add it to the library instead,
where its part number, mass, specification and download address are recorded with it. And keep
FreeCAD's **Use relative paths when saving external links** switched on, or your next save turns
these links into paths that only work on your computer.

If you clone this repository, fetch the library with it:

```bash
git submodule update --init --recursive
```

Without that step, `modules/stoq/` is empty and both assemblies open with broken links.

## Starting the first model

Geometry belongs to a module, not to this folder, so the first model starts under
`modules/<module>/cad/`. Copy the seed
[`doqs/templates/cad/build_model.py`](../doqs/templates/cad/build_model.py) there and replace its
`build()` function. Copy nothing else: transactions, save discipline and fingerprinting live in
`doqs/scripts/cad_build.py` and reach the seed on their own. `validate_cad.py` fails on a per-module
copy of a doqs tool.

```bash
python doqs/scripts/resolve_params.py --module modules/<module> --model default
FreeCADCmd modules/<module>/cad/build_model.py
bash doqs.sh check --only cad
```

`FreeCADCmd` stays as it is: it runs the build script inside FreeCAD, which
`doqs.sh` cannot reach. The same is true of the parameter sync below.

**Never edit `.FCStd` files directly.** After changing parameters, run the doqs sync script from the
module root — in the FreeCAD Python console:

```python
exec(open("doqs/scripts/cad_sync_params.py").read())
sync_active()
```
